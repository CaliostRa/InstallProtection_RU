# InstallProtection_RU

Русский форк `Install Protection` / `安装防护模块` с сохранением исходной логики hooks, package name `com.install.appinstall.xl` и совместимости с `LSPosed` и `LSPatch`.

Этот репозиторий не является официальным upstream-репозиторием автора. Китайский оригинал README сохранён в [README_CN.md](README_CN.md). Оригинальный upstream: <https://github.com/yijun01/com.install.appinstall.xl>.

## Что это за модуль

`Install Protection` — Xposed/LSPatch-модуль для Android, который перехватывает проверки установки приложений и связанные эвристики. Модуль умеет:

- подменять ответы `PackageManager` и списки установленных приложений;
- скрывать следы модификаций, `Xposed`, `LSPatch`, `Root`, `ADB`, часть сетевых признаков;
- перехватывать переходы между приложениями, проверку разрешений, часть сценариев принудительного выхода;
- показывать плавающее окно управления прямо внутри целевого приложения.

Русифицированный форк сохраняет это поведение и меняет только интерфейс, строки диалогов, overlay, пользовательские логи и документацию.

## Основа форка

- Исходная база: upstream `2.1.68`, `versionCode 241`, `versionName 2.1.68`
- Актуальный upstream source commit: `5e584196f38568ccfd9a68b4d54a9a1117179010`
- Официальный upstream release: `241-2.1.68`
- Package name в форке не менялся: `com.install.appinstall.xl`
- Xposed entry point не менялся: `com.install.appinstall.xl.HookInit`

Это сделано специально, чтобы не ломать работу `LSPatch`, `LSPosed` и существующую hook-логику.

## Чем форк отличается от оригинала

- Основной интерфейс переведён на русский для локали `ru`.
- Для остальных локалей остаётся оригинальный язык upstream.
- Название приложения в русской локали: `InstallProtection_RU`.
- README по умолчанию русский, но исходный китайский README сохранён отдельно.
- Сборка выполняется из исходников, без патчинга готового APK.

## Установка через LSPosed

1. Установите APK модуля `InstallProtection_RU`.
2. Откройте `LSPosed`.
3. Найдите модуль `InstallProtection_RU` и включите его.
4. Добавьте в scope целевое приложение.
5. Перезапустите целевое приложение.

Не включайте модуль для системных приложений, если не понимаете последствия.

## Установка через LSPatch без root

1. Откройте `LSPatch`.
2. Выберите APK целевого приложения.
3. Выберите режим `Embedded mode`.
4. Отметьте модуль `InstallProtection_RU`.
5. Нажмите `Patch`.
6. Установите получившийся пропатченный APK.

Важно: патчить нужно именно целевое приложение, в котором должны скрываться проверки установки. VPN-клиент, браузер или другое стороннее приложение патчить вместо цели не нужно.

## Типовой rootless workflow

`LSPatch` → выбрать целевой APK → `Embedded mode` → выбрать `InstallProtection_RU` → `Patch` → установить пропатченный APK

## Как включить и открыть управление

- Главное окно модуля показывает статус активации и основные разделы настроек.
- Внутри целевого приложения модуль может показывать плавающее окно.
- Нажатие по overlay открывает меню быстрых действий.
- Долгое нажатие скрывает overlay.
- Если overlay скрыт, его можно вернуть способами, которые предусмотрены upstream для текущей версии модуля.

## Основные пункты интерфейса

- `Защита установки` — основной режим подмены установки.
- `Управление пакетами` — список пакетов и правила подмены.
- `Дополнительные настройки` — доступ к расширенным разделам.
- `VPN и прокси` — настройки скрытия VPN/proxy-признаков.
- `Скрытие следов` — скрытие `Xposed/LSPatch`, `Root`, `ADB` и похожих признаков.
- `Журнал в реальном времени` — просмотр пользовательских runtime-логов.
- `Экспорт конфигурации` / `Импорт конфигурации` — перенос настроек между экземплярами.

## Сборка

Из чистого clone проект собирается стандартным Gradle-сценарием:

```bash
./gradlew clean
./gradlew assembleDebug
./gradlew assembleRelease
```

Если переменные подписи release не заданы, собирается unsigned release APK. Приватные ключи подписи в репозиторий не добавляются.

Артефакты появляются здесь:

- `APP/installCheck/app/build/outputs/apk/debug/InstallProtection_RU-2.1.68-debug.apk`
- `APP/installCheck/app/build/outputs/apk/release/InstallProtection_RU-2.1.68-release-unsigned.apk`

## Подпись и Releases

Для локальной подписанной release-сборки задаются только внешние переменные:

```bash
export ANDROID_KEYSTORE_FILE=/secure/path/install-protection-ru.jks
export ANDROID_KEY_ALIAS=install-protection-ru
export ANDROID_KEYSTORE_PASSWORD='...'
export ANDROID_KEY_PASSWORD='...'
./gradlew assembleRelease
```

В GitHub Actions используются Secrets с теми же именами, но вместо пути передаётся `ANDROID_KEYSTORE_BASE64`. Их следует хранить в защищённом Environment `release`. На обычных push/PR собираются debug и unsigned release APK. При push тега CI отдельно скачивает готовый unsigned artifact, подписывает его через `apksigner`, проверяет подпись, создаёт SHA256-файл и публикует GitHub Release. Ключ не передаётся Gradle-коду и не сохраняется в репозитории.

Тег релиза должен начинаться с upstream `versionCode`, например:

```text
v241-2.1.68-ru1
```

Такой формат нужен встроенной проверке обновлений, которая сравнивает первое число тега с установленным `versionCode`.
Каждый следующий публикуемый APK должен увеличивать `versionCode`, а тег обязан начинаться с того же числа; иначе Android и встроенная проверка обновлений не смогут корректно отличить новую сборку.

Важно: package name сохранён от upstream, но постоянная подпись RU-форка будет другой. Android не позволит установить RU APK как обновление поверх официального APK автора. Перед переходом экспортируйте конфигурацию, удалите официальную сборку и установите RU APK; последующие RU-релизы должны всегда подписываться одним и тем же постоянным ключом.
