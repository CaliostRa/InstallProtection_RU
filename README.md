# InstallProtection_RU

Русский форк `Install Protection` / `安装防护模块` для Android с сохранением основной hook-логики upstream, package name `com.install.appinstall.xl` и совместимости с `LSPosed` и `LSPatch`.

**[Скачать последнюю версию APK](https://github.com/CaliostRa/InstallProtection_RU/releases/latest)**

Этот репозиторий не является официальным upstream-репозиторием автора. Оригинальный проект: <https://github.com/yijun01/com.install.appinstall.xl>. Китайский README upstream сохранён в [README_CN.md](README_CN.md).

## Что это за модуль

`Install Protection` — Xposed/LSPatch-модуль, который перехватывает проверки установки приложений и связанные эвристики. Модуль умеет:

- подменять ответы `PackageManager` и списки установленных приложений;
- скрывать следы модификаций, `Xposed`, `LSPatch`, `Root`, `ADB` и часть сетевых признаков;
- перехватывать переходы между приложениями, проверку разрешений и часть сценариев принудительного выхода;
- показывать плавающее окно управления внутри целевого приложения.

Функциональная hook-логика upstream сохраняется. Изменения RU-форка касаются русской локализации, пользовательских строк и логов, документации, адреса проверки обновлений и инфраструктуры сборки/релизов.

## Установка через LSPosed

1. Скачайте APK из [последнего Release](https://github.com/CaliostRa/InstallProtection_RU/releases/latest) и установите его.
2. Откройте `LSPosed`.
3. Найдите модуль `InstallProtection_RU` и включите его.
4. Добавьте в scope целевое приложение.
5. Перезапустите целевое приложение.

Не включайте модуль для системных приложений, если не понимаете возможные последствия.

## Установка через LSPatch без root

1. Установите APK модуля `InstallProtection_RU`.
2. Откройте `LSPatch`.
3. Выберите APK целевого приложения.
4. Выберите режим `Embedded mode`.
5. Отметьте модуль `InstallProtection_RU`.
6. Нажмите `Patch`.
7. Установите получившийся пропатченный APK.

Важно: патчить нужно именно целевое приложение, в котором должны скрываться проверки установки. VPN-клиент, браузер или другое стороннее приложение патчить вместо цели не нужно.

## Как открыть управление

- Главное окно модуля показывает статус активации и основные разделы настроек.
- Внутри целевого приложения модуль может показывать плавающее окно.
- Нажатие по overlay открывает меню быстрых действий.
- Долгое нажатие скрывает overlay.
- Если overlay скрыт, его можно вернуть способами, предусмотренными upstream для текущей версии модуля.

## Основные пункты интерфейса

- `Защита установки` — основной режим подмены установки.
- `Управление пакетами` — список пакетов и правила подмены.
- `Дополнительные настройки` — расширенные параметры.
- `VPN и прокси` — скрытие VPN/proxy-признаков.
- `Скрытие следов` — скрытие `Xposed/LSPatch`, `Root`, `ADB` и похожих признаков.
- `Журнал в реальном времени` — просмотр runtime-логов.
- `Экспорт конфигурации` / `Импорт конфигурации` — перенос настроек между экземплярами.

## Переход с официальной версии upstream

Package name RU-форка сохранён от upstream, но APK подписан другим постоянным ключом. Поэтому Android не позволит установить `InstallProtection_RU` как обновление поверх официального APK автора.

Перед переходом:

1. Экспортируйте конфигурацию в официальной версии.
2. Удалите официальный APK upstream.
3. Установите APK `InstallProtection_RU` из Releases.
4. При необходимости импортируйте конфигурацию.

Последующие RU-релизы должны подписываться тем же постоянным ключом.

Сборки `ru1` и `ru2` имели одинаковую Android-версию `241 / 2.1.68`. Начиная с `ru3` номер сборки увеличен: обновление можно установить поверх предыдущего RU APK с сохранением данных. В Komi Store приложение должно быть связано с `CaliostRa/InstallProtection_RU`; если обновление не предлагается, скачайте APK из последнего Release и установите поверх. В режиме LSPatch Embedded обновление установленного модуля не заменяет его копию внутри целевого APK — для неё нужно повторное патчирование.

## Для разработчиков

Быстрая сборка:

```bash
./gradlew clean
./gradlew assembleDebug
./gradlew assembleRelease
```

Без настроенной подписи release-сборка создаётся как unsigned APK. Приватные ключи подписи в репозиторий не добавляются.

Подробности по локальной подписи, GitHub Actions, тегам и `versionCode`: [docs/BUILD_AND_RELEASE.md](docs/BUILD_AND_RELEASE.md).

Важно: встроенный update-checker сравнивает первое число тега Release с установленным Android `versionCode`. Поэтому новый релиз, который должен определяться автоматически, должен иметь увеличенный `versionCode`, а тег — начинаться с этого же числа. Суффикс `ruN` сам по себе не считается новой версией.
